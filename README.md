# 本地语音 · Android

配合 Fcitx5 for Android 使用的本地语音输入键盘。按住说话，松手输入，上滑取消；中途停顿不会结束录音。

## 使用

1. 安装 GitHub Actions 构建的 `LocalVoiceInput-arm64.apk`（Android 8.0+，ARM64）。
2. 打开「本地语音」，下载一个语音包，推荐先使用 SenseVoice。
3. 点击「启用本地语音键盘」和「允许使用麦克风」。
4. 从 Fcitx5 的语音入口进入，或使用系统键盘切换器切到「本地语音」。
5. 按住按钮说话，松开后识别并输入。上滑再松手会取消。

主界面采用暗色风格。左上角返回键盘，右上角打开设置；文字提示区下方的整片面板都可按住说话，中央小按钮只作操作提示。

语音包已下载并授权麦克风后，即使首次加载尚未结束，也能立即按住录音。录音与准备并行；松手时若尚未就绪，音频只在内存中等待，准备完成后自动识别。退出页面会丢弃等待中的录音。

## 语音包

| 名称 | 下载量（约） | 定位 |
| --- | --- | --- |
| SenseVoice Small INT8 | 228 MiB | 默认，中英混合输入 |
| Paraformer INT8 | 213 MiB | 中英输入对照 |
| Paraformer 实时中英版（含标点） | 298 MiB | 实时预览与自动标点 |

下载只获取 INT8 权重和配套词表，不打包浮点权重。使用固定版本和逐文件 SHA-256 校验，下载完整并校验成功后才显示可使用。支持暂停与续传；被系统结束后再次点击下载可继续。下载时请保持设置页打开。


## 键盘高度与切换

设置页可调整 200–500 dp 的面板高度，默认 320 dp。将其调到与 Fcitx5 键盘一致，可减少宿主应用因高度不同而移动。语音输入法自身窗口关闭切换动画，横屏也不进入全屏编辑模式；系统或另一个输入法的切换动画仍由其自身控制。

## 快速启动

默认开启。语音包下载后会提前加载，共享识别器在输入法关闭时不主动卸载。只在应用进程内缓存一个模型，不启动前台保活服务、不显示常驻通知、不申请通知权限，也不定时唤醒或重启进程。切换模型会释放旧模型。

Android 或厂商系统仍可能回收进程，回收后首次使用会重新准备；模型加载期间仍可先录音。关闭快速启动时释放缓存，之后输入法服务销毁时也释放模型。系统录音指示由 Android 管理，录音期间正常显示。

## 隐私

- 音频只在内存中处理，不保存、不上传、不记录日志。
- INTERNET 仅用于用户主动下载语音包、检查和下载应用更新，识别过程完全离线。
- 下载模型存放在应用私有、不备份目录，无需文件访问权限。
- 仅在按住说话或主动无障碍点按录音期间使用麦克风；离开输入法立即停止。
- 使用会话与输入位置检查，过期结果不提交到新输入框。

## 构建

JDK 17，Android SDK 与版本见 `.github/workflows/android.yml`。

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

不需要预先下载模型即可构建。推送 main 或手动运行 **Build Android APK**，成功后在该次 Actions 页下载 `LocalVoiceInput-arm64` artifact，解压得到可安装的 Debug APK。所有发布构建必须使用仓库 Actions Secrets 中的固定签名。构建前核对 `.github/signing-certificate.sha256`，打包后再核对 APK 签名；密钥缺失或指纹不一致直接失败，不自动生成新密钥。

已按仓库所有者授权配置固定签名，使用：`ANDROID_SIGNING_KEYSTORE_BASE64`、`ANDROID_SIGNING_STORE_PASSWORD`、`ANDROID_SIGNING_KEY_ALIAS`、`ANDROID_SIGNING_KEY_PASSWORD`。此前默认 Debug 密钥的实际路径为 `/home/runner/.config/.android/debug.keystore`，旧缓存配置未保存该文件；旧 runner 的私钥无法从 APK 公钥证书恢复。如果改用新固定密钥，已安装的不同签名版本需要重装一次，之后才可持续覆盖升级。

模型切换、常驻内存和麦克风行为需要在 ARM64 真机上验证；CI 单元测试与构建不能替代真机效果和耗时测试。

## 项目与模型

基于 Mesong21/LocalVoiceInputForAndroid；推理使用 sherpa-onnx。模型目录和校验信息见 `app/src/main/assets/model-catalog.json`，均来自 sherpa-onnx 维护者提供的 Hugging Face 导出。

- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)
- [SenseVoice](https://github.com/FunAudioLLM/SenseVoice)
- [Paraformer](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-paraformer/paraformer-models.html)
- [Fcitx5 for Android](https://github.com/fcitx5-android/fcitx5-android)

代码与模型的许可证及再分发要求需分别遵守。

## 实时中英输入（1.2.0）

在设置中下载并选择「Paraformer · 实时中英版（含标点）」，约 298 MiB，包含 encoder/decoder INT8、词表及 CT-Transformer INT8 标点模型。按住讲话时在语音面板预览文字，松手后刷新流式尾帧并自动补标点，然后一次提交到目标文本框。停顿不会自动提交，单次上限 60 秒，上滑取消。首次加载时可以先录音，模型准备后追上进度。

这一路径不使用 SenseVoice、不进行离线 ASR 后校准，也不承诺无限回改已经稳定的前文。预览暂不实时添加标点，标点在松手后统一恢复，减少反复推理和文字抖动。读取音频与推理分别运行；有上限的内存队列采用合并调度，不为每次读取堆积 worker 任务。取消后清空待处理数据，过期结果不提交。共享引擎切换时释放旧模型；快速启动仍无常驻通知。

模型来源：流式中英 Paraformer 使用 sherpa-onnx 维护者的 Hugging Face 导出，标点使用 ranger810 镜像的 CT-Transformer INT8 ONNX；模型清单固定源提交、字节数和 SHA-256，下载完成校验后才可使用。对应模型及转换代码许可应分别遵守。

实机验收应覆盖：首次加载立即讲话、中英混说、长停顿、60 秒上限、上滑取消、切换输入框、删除模型、切回其他语音包及低高度面板。CI 不能替代 ARM64 麦克风与 native 推理性能实测。

## 纠错面板（1.3.0）

语音面板右上角、设置图标左侧提供「纠错」开关，默认关闭，状态会保存。开启后，松手识别完成先显示校对面板，点击「输入」才提交。点击选择词块，横向滑动连续选择多个词，上下滑动滚动长文本；「按词/按字」切换到更细粒度。可删除所选内容、撤销、重录或取消。


候选功能需要至少另一款已下载且适用的语音包。后台模型切换复用同一串行 worker，释放原模型后加载另一模型，以降低同时驻留的内存；代价是下一次录音可能需要重新加载主模型。默认关闭纠错时仍直接提交，流式主识别不自动调用 SenseVoice。

纠错录音只暂存于内存，确认输入、取消、重录或离开输入面板时清除，不保存、不上传。校对期间可以继续按原有方式返回键盘或进入设置，但未提交内容会丢弃。

## 简化纠错（1.3.1）

纠错面板底部只保留「按住重录」和「输入」。点选或滑选字词后，候选直接显示在面板内，删除仅在选词时出现；顶部保留紧凑的按字/按词及撤销。重录按下即录音、松手识别，上滑取消。录音时隐藏重复状态标题，实时文字使用主区域。

输入位置通过输入会话编号和当前有效连接检查，避免依赖 InputConnection 包装对象身份。候选不再打开抢占焦点的窗口；输入和重录可以取消尚在进行的候选生成，不必等候选任务结束。

按需依次调用其余已下载语音包，并对选词对应的建议去重。当前共有三个语音包，因此最多可有两款其他模型的不同建议；候选不足时不人为凑数。结果按本次录音缓存。它们属于多模型建议，尚非同一模型的 N-best。

## 固定录音栏与局部重说（1.3.2）

待机、录音、处理和纠错共用同一底栏录音按钮，位置和尺寸固定；输入按钮显示/隐藏不移动录音按钮。纠错仅按 Unicode 字符簇选择，支持连续滑选，移除按字/按词切换和下方说明文案。

选中文字后按住录音，只用新识别的内容替换固定选区，保留前后文字；没有选区时替换整段。取消、过短或识别失败保留原稿，替换结果可撤销。局部替换自动移除新片段两端的句读，避免插入句中多余句号。

局部重说后，旧整段录音与新文本不再对应，故解除旧音频引用、清除旧候选；不把局部录音当整段录音送去生成候选。尚未实现语音片段对齐和拼接。新一轮整段录音仍可正常生成多模型候选。

## 字块布局与纠错状态（1.3.3）

字块采用铺满整行的等宽字符网格，收紧左右内边距，不显示横竖滚动条。文字区按可用高度计算整数行，滚动停止后吸附到整行边界。普通上下滑动用于浏览；横向起滑后可连续跨行选择，也可长按后向任意方向选择。选取时靠近上下边缘可自动滚动。

选择完成后，候选栏固定位置显示「正在纠错…」「候选已就绪」「无其他候选」或失败状态；缺少第二个语音包、局部重说后没有整段音频时也明确说明。失败状态可以点击重试；部分模型失败时仍保留已成功的候选。原有底栏按钮位置不变。

## 应用内更新

设置页底部提供「检查更新」，仅手动检查本仓库 GitHub Releases 的最新正式版。发现新版后点击「下载并安装」，下载完成核对 SHA-256、应用包名、递增版本号和与当前安装一致的签名，再打开系统安装程序。首次需要允许本应用安装未知来源应用；返回后继续安装，最终由用户在系统界面确认。下载失败可以重试，无后台检查或更新通知。

main 构建成功并验证固定签名后，会按 versionName 发布 `vX.Y.Z` Release，附带 `LocalVoiceInput-arm64.apk`。已存在的版本不覆盖；每次发布需递增 versionCode 和 versionName。

## 文字整理（1.4.0）

在设置页下载「文字整理包」（约 397 MB），开启纠错及「显示文字整理按钮」，在纠错区手动点击「整理」。采用 Qwen3-0.6B Q4_K_M，关闭思考模式，进行轻度去赘词、去重复、理顺语病；只在上下文明确时尝试修正识别错词。识别原文先进入文字确认区，只有点击「整理」才进行处理，点击「输入」才写入目标文本框；结果发生变化时可「撤销」恢复识别原文。数值、英文片段、否定附近的文字或关键态度词发生变化、结果异常、超时或失败时保留原文。此模型不读取音频，不能保证纠正同音词，仍需核对专名和否定表达。

推理完全离线，下载固定提交和 SHA-256 校验的模型；支持暂停、续传和删除。llama.cpp 固定为 `a7a98e0fffed794396b3fbad4dcdbbc184963645`（b6500，MIT），Qwen3 与 Unsloth 量化权重为 Apache-2.0。两线程 CPU 推理，与 ASR 串行运行；整理模型在闲置约五分钟后释放，不申请后台服务、通知或唤醒锁。首次整理需加载模型，会增加等待时间。最多处理 1000 字且受 2048 token 上下文、768 token 输出和约 35 秒推理时限约束，超出时保留原文；取消或切换输入框会丢弃结果。

输入面板底部固定提供删除和换行键：确认区内优先修改选中文字，否则编辑末尾；没有待确认文字时作用于当前文本框。录音或处理期间不执行这两个按键，避免改变待写入的输入位置。

1.4.1 验证：在 Linux 主机使用同一固定量化文件与生成逻辑进行构造文本抽测，成功去掉「这个功能这个功能」等重复；也观察到模型会错误改变否定所指对象，因此新增否定邻近文字和态度词检查，异常时回退原文。此检查偏保守，不能保证语义等价；安卓端推理速度、内存、键盘交互仍需 ARM64 真机验证。

## 1.4.2 交互调整

删除、换行移至底部右侧，使用统一 24dp 矢量图标与 48dp 点击区域。文字整理归于纠错：先开启纠错，再启用「显示文字整理按钮」，在纠错区手动点击「整理」才加载并运行 Qwen。录音结束、选字、提交都不会触发文字整理；关闭纠错后不显示入口、不执行整理。整理期间禁用草稿编辑和提交，完成后可撤销。

## 1.4.3

确认区中「输入」与「按住重说」互换，输入占用主要宽度，重说保持 96dp，删除和换行仍位于右侧。Qwen 仅手动触发，运行后缓存模型及固定提示词的 KV 状态五分钟，避免短时间内重复加载、分配上下文和计算固定提示词。每轮结束清除用户文本对应的 KV；取消、失败清空上下文。此优化主要改善再次整理的等待，首次加载及逐字生成仍然需要时间。

缓存回归抽测（Linux 主机，构造文本）：按 A→B→A 连续整理，耗时分别约 5830/1721/1082 ms；两次 A 输出一致，B 保留自己的数字和英文信息。此结果验证缓存复用及文本隔离，不代表安卓设备性能。

## 1.4.4 主操作修复

移除语音重说替换流程。普通页面显示宽的「按住说话」；纠错确认页面隐藏录音按钮，只显示宽的「输入」。提交、取消、切换输入位置后恢复普通页及录音按钮文字，删除和换行保持右侧。文字整理仍须手动点击。

小模型调研抽测：官方 MiniMind2 104M 的 Q4 文件约 63.7 MB，在构造中文清理任务中出现无关输出；Gemma 3 270M IT Q4_K_M 文件约 253 MB，主机端生成更快，但两种提示格式下常保留重复和语气词。本版不将它们直接替换为默认整理器，避免以明显降低整理效果换取更小体积。测试使用构造文本及原生推理逻辑，不代表 ARM64 实机性能。参考来源：jingyaogong/MiniMind2-gguf、google/gemma-3-270m-it、unsloth/gemma-3-270m-it-GGUF。
